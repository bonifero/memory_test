# Исследование кратковременной памяти

Учебный проект по ПЧМИ. Тестируемому показывают набор символов (римские цифры и/или пиктограммы, мелкие и крупные
вперемешку) на фиксированное время, затем он отмечает те, что запомнил. Порядок не важен.

## Гипотезы и план эксперимента

- **H1.** Пиктограммы запоминаются лучше, чем римские цифры.
- **H2.** Крупные символы запоминаются лучше, чем мелкие.

Каждый тестируемый проходит 4 блока. В каждом наборе символы двух видов, примерно поровну:

| Блок | В одном наборе |
|---|---|
| A | Римские цифры: крупные и мелкие |
| B | Пиктограммы: крупные и мелкие |
| C | Мелкие римские цифры и крупные пиктограммы |
| D | Мелкие пиктограммы и крупные римские цифры |

- В блоке 3 испытания: 3, 5 и 8 символов показываются 3, 5 и 8 секунд. Всего 12 испытаний,
  у всех тестируемых одинаковое число символов и одинаковое время показа.
- Наборы из 3 и 5 символов делятся неровно в разные стороны (2+1 и 2+3), набор из 8 — поровну, так что за блок
  показывается ровно по 8 символов каждого вида. Цифры в одном наборе не повторяются.
- Порядок блоков чередуется по латинскому квадрату (4 варианта по кругу), чтобы убрать эффект усталости и обучения.
- Крупные символы ровно в 3 раза выше мелких. Карточки и их расположение одинаковые, цвет символов один и тот же.
- На экране ответа все варианты одного нейтрального размера. В блоках A и B — 10 вариантов в форме блока,
  в блоках C и D — две группы: 10 римских цифр и 10 пиктограмм, символ нужно отметить в том виде, в каком он был показан.
- Точность испытания = (показано − пропущено − лишние) / показано.

Гипотезы проверяются по отдельным символам: для каждого участника считается доля вспомненных символов каждого вида
(римские/пиктограммы × мелкие/крупные, по 16 символов на вид), уровень фактора — среднее двух его видов. Сравнение —
парный t-тест по участникам (α = 0,05). Блоки A–D вместе покрывают все 4 вида поровну, поэтому план остаётся
сбалансированным 2×2. Лишние ответы нельзя отнести к размеру, они учитываются только в точности испытания.
Статистика считается на бэкенде (`backend/src/stats.ts`) только по сессиям текущего протокола (`mixed-v1`);
сессии старого протокола видны в списке участников с пометкой, но в статистику и выгрузки не попадают.

## Структура

```
backend/    Node 22 + Express + SQLite (better-sqlite3), TypeScript
frontend/   React + Vite + TypeScript; в контейнере раздаётся nginx
.github/workflows/ci.yml  сборка и тесты
.github/workflows/cd.yml  деплой на сервер по SSH
```

| URL | Что там |
|---|---|
| `/` | Тестирование |
| `/admin` | Админ-панель (Basic auth, `admin` / `admin`): статистика, результаты по участникам, выгрузка CSV, удаление |
| `/api/health` | Проверка работоспособности бэкенда |

API бэкенда:

- `POST /api/sessions` — сохранить результаты сессии;
- `GET /api/sessions/next-order` — номер порядка блоков для нового участника;
- `/api/admin/*` — админский API под Basic auth: `sessions`, `sessions/:id`, `sessions/delete`, `export.csv`, `stats`, `stats.csv`.

Фронтенд обращается к нему через nginx своего контейнера: `/api/*` и `/admin/api/*` → `/api/admin/*`.

CSV выгружаются с разделителем `;` и десятичной запятой, поэтому сразу открываются в русском Excel.

## Запуск локально

```bash
cp .env.example .env
docker compose up -d --build
```

- Тест: http://127.0.0.1:9096
- Админка: http://127.0.0.1:9096/admin
- Бэкенд напрямую: http://127.0.0.1:9095/api/health

Порты 9095 (бэкенд) и 9096 (фронтенд) опубликованы только на `127.0.0.1` хоста: к ним обращается системный nginx.
Внутри сети Docker сервисы общаются как `backend:3000` и `frontend:80`. База SQLite лежит в volume `db-data`
(`/data/results.db` в контейнере бэкенда) и сохраняется при пересоздании контейнеров. Не запускайте
`docker compose down -v`, если данные нужны.

Разработка без Docker:

```bash
cd backend && npm ci && npm run dev     # :3000
cd frontend && npm ci && npm run dev    # :5173, /api проксируется на :3000
```

## Системный nginx на сервере

Достаточно проксировать домен целиком на фронтенд-контейнер. API и админку он проксирует сам:

```nginx
location / {
    proxy_pass http://127.0.0.1:9096;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## CI/CD

- **CI** запускается на каждый push и PR: `npm ci`, проверка типов, тесты статистики, сборка бэкенда и фронтенда,
  `docker compose build`.
- **CD** запускается после успешного CI в ветке `main` (или вручную через *Run workflow*):
  1. копирует проект на сервер в `~/memory-test`;
  2. записывает `.env` со статичными значениями из workflow;
  3. выполняет `docker compose up -d --build`;
  4. проверяет health обоих контейнеров.

Секреты репозитория (*Settings → Secrets and variables → Actions*):

| Секрет | Значение |
|---|---|
| `SERVER_HOST` | адрес сервера |
| `SERVER_USER` | пользователь SSH; должен иметь доступ к `docker` (группа `docker`) |
| `SSH_PRIVATE_KEY` | приватный ключ; публичная часть должна быть в `~/.ssh/authorized_keys` на сервере |

На сервере нужны Docker с плагином Compose v2 и `curl`.
